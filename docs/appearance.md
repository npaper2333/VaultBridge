# 外观设置 · 两端 0.5.2 预发布

本版将外观选项集中到“设置”：主题色可跟随 Obsidian 或自定义，深浅模式可选浅色、深色、系统或 Obsidian，两项独立生效。手动设置保留，不被定期检测覆盖；以下读取与回退规则仅影响选择了跟随的项。完整说明见 [设置与建议交流](settings-feedback.md)，验证边界见 [testing.md](testing.md)。

Android 的自定义颜色窗口提供五个有名称的实际色块、选中标记、色值输入，以及色相/饱和度/明亮度滑杆。下方用当前深浅背景预览主要按钮，按钮文字自动选用可读的黑色或白色。输入不完整时保留最后有效预览并禁用“应用”；“取消”不写设置，“还原本次修改”回到打开窗口时的颜色。弹窗内容可滚动，避免预设色被通用文字着色覆盖成黑点。Windows 保留其原生颜色选择方式。

电脑与手机/平板固定使用“晴湖书架”的侧栏、圆角卡片与留白；窄屏平板使用可滚动导航。取消风格菜单和三个手动风格入口。外观页显示当前检测来源、深浅背景、强调色及检测结果，可点“重新检测外观”。

## 读取与刷新

- 两端分别读取当前选择的 Obsidian 库根目录下 `.obsidian/appearance.json`，只读且最多 64 KiB。选择库即授权应用读取其中的基础外观信息。
- `theme=obsidian` 使用深色，`theme=moonstone` 使用浅色；`system`、空值或缺少字段跟随设备系统。强调色使用有效的 `accentColor` 十六进制 RGB，未指定时使用紫色 `#7f6df2`。
- 电脑每两秒检查一次，平板回到前台、切换库和手动刷新时检测。平板在后台读取文件提供器，任务中等待任务完成再更新界面，不丢失尚未保存的导入目录输入。
- 未选择库、配置缺失、授权失效、损坏或超限时明确显示结果，使用系统深浅色和默认紫色；切换库不沿用另一库的颜色。
- Windows DPI 配置继续随 EXE 分发，保持原生清晰绘制。

## 颜色与范围

浅色背景用白/浅灰，深色背景用近黑/深灰，文字分别用深灰/近白。侧栏、输入框、普通按钮、任务记录和提示背景保持中性，不用主题色混色铺底。强调色来自 Obsidian 或自定义设置，仅在开始分享、导出、同步、导入等少量主要操作及少量重要状态文字使用；主要按钮文字按对比选择黑或白。

0.3.1 采用更简洁的标题、按文字宽度排列的操作和适度圆角。电脑：卡片 10、按钮和输入框 6；平板：卡片 12、按钮 7。宽屏保持晴湖侧栏，选中项用中性灰底。圆角是实际填充形状，键盘焦点和不可用状态仍须清晰。颜色与布局独立，深色不改变侧栏结构。

电脑 0.3.3 的页面、任务记录与目录滚动条跟随所在控件的底色，滑块和箭头使用中性灰；地址框、箭头和列表项也跟随深浅色。控件保留原生滚动、键盘选择和文本选择行为，应用不修改 Windows 全局主题。

电脑 0.3.4 的滚动条独立绘制并使用缓冲，快速滚动时也保持当前主题灰色；内容仍使用原生控件，长目录列表补齐隐藏原生滚动条后的滚轮兼容处理。

平板 0.3.4 将原生主题应用到主页面、圆角弹窗、输入框、列表、复选框和扫码页。卡片约 12 dp、按钮 7 dp、输入框 6 dp 的圆角，文字按设备密度直接绘制。普通按钮、选择状态和滚动条用中性灰；主要操作与少量确认文字使用可读的强调色。状态栏与导航栏跟随应用基础深浅色。

平板原生滚动条直接使用灰色滑块和透明轨道，列表缓存底色匹配主题，禁用大块边缘发光；不采用绘制白底后再覆盖的方式。构建和配色回归不能代替 MatePad 上的真实快速滑动、长列表复用和弹窗显示检查。

跟随基础深浅色与强调色，不执行主题 CSS、插件或 CSS snippets。自定义 Obsidian 配置目录目前需使用默认 `.obsidian`；检测状态会明确标注读取路径。没有读取其他库或 Obsidian 全局目录，也没有更改 Obsidian 本身的外观或同步它的配置文件。

参考：[Obsidian 外观说明](https://obsidian.md/help/appearance)、[库配置目录说明](https://obsidian.md/help/configuration-folder)。JSON 字段属于当前配置文件约定；未知模式或无效颜色采用上述回退，不推断任意 CSS 的最终渲染颜色。
