# 应用更新

**应用内更新入口从 0.4.2 起提供。旧 0.4.0 / Android 0.4.1 没有此入口，需先手动安装对应平台新版，可直接装 Android 0.4.3 / Windows 0.4.2。** 电脑解压其对应 ZIP，保留 EXE 旁同名 `.exe.config`；Android 用同签名 APK 覆盖安装，不先卸载。

## 检查与下载

启动后在后台检查固定仓库 `npaper2333/VaultBridge` 的公开 Release，包含本项目预发布版本。Windows 打开“外观与说明”→“版本与更新”，Android 打开“设置与说明”→“应用更新”，可查看当前版本、新版说明和下载操作，手动检查或关闭启动检查。检查本身不自动下载、安装或中断分享。

数字版本高于当前版本、且存在对应平台精确文件名的资产才会提示更新。点击下载后先核对 GitHub 提供的 SHA-256 digest；没有有效 digest 时仅提供发布页，请手动下载并核对 Release 校验文件。下载中断、校验失败、API 限流或离线时显示明确状态，不能把检查失败当作“已是最新”。仍可继续使用本机笔记、ZIP 导入与局域网传输。

0.4.3 只更新 Android；Windows 保持 0.4.2，检查器会跳过不含对应 Windows 资产的 Release。这不表示检查失败，也不需要下载改名的 Desktop 0.4.3。

## Android：由系统确认覆盖安装

1. 点击下载，等待完整校验；应用还会核对 APK 包名、版本及当前安装签名。
2. 点击“安装更新”。系统若尚未允许 VaultBridge 安装应用，按提示打开系统授权页，由你授予这个来源权限；返回 VaultBridge 后，再次点击“安装更新”，应用会重新核对安装包，再打开系统安装确认页。保持系统安全检查开启。
3. 系统显示安装确认后选择覆盖安装。不能静默安装；取消或失败不会清除原应用与笔记。

只有系统完成安装才表示升级成功。重新打开应用核对版本；自行签名的 APK 与官方签名不一致时，不能用官方包直接覆盖。不要为解决签名冲突先卸载唯一数据来源。手机与平板使用同一个 APK，静态界面称呼按完整屏幕尺寸调整，不修改文件名、正文或配对设备名。

## Windows：点击后切换新版

下载完成并通过 SHA-256 校验后，应用把便携 ZIP 解包到新的本地私有更新目录，检查安全路径、大小及 EXE 和同名配置的完整性。点击“切换到新版”前会说明：当前分享将停止，正在进行的传输需要稍后继续。

由你明确点击切换后才启动新版并退出旧进程。旧 EXE、旧下载和设置保留，不覆盖运行中的文件；新版读取同一份本地设置。打开新版后按需重新开始分享。Windows EXE 仍没有发行者证书，GitHub digest 校验不等于独立的发行者签名验证。

已知验证边界：0.4.2 在自动执行环境建立 HTTPS 时遇到 `SEC_E_NO_CREDENTIALS`，对照请求同样失败；不能据此判定所有桌面都失败，也不能宣称实际下载/切换已验收。遇到问题可从原 Release 页面手动下载，详细记录见公开仓库的验证说明。

## 网络与数据

更新只读取公开 GitHub API 和该仓库的官方 HTTPS 资产，不需要 GitHub 登录或 token，不发送笔记、库目录、配对凭据或设备名称。GitHub 更新需要互联网；笔记仍保存在你的设备中，“免费、无云端笔记同步”的规则不变。访问服务会产生通常的网络连接信息，不能把不发送笔记理解为完全不联网。

下载文件、缓存、解包和历史版本不自动清理。空间不足时先按提示处理，不把失败当作安装成功。目标平板的系统安装、来源权限与 Windows 实际切换仍按 [验收清单](acceptance.md)进行人工验证。

GitHub Release 字段见 [GitHub 官方文档](https://docs.github.com/en/rest/releases/releases)，Android 安装来源检查见 [PackageManager.canRequestPackageInstalls](https://developer.android.com/reference/android/content/pm/PackageManager#canRequestPackageInstalls())。
